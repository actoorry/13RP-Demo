## 一、核心概念定义

### 1.1 什么是"十三维"

13RP 将企业决策空间建模为 **13 个维度**：

| 层 | 维度 | 本质问题 |
|:--:|------|---------|
| 1RP | 资源维 | 你有什么？ |
| 2RP | 流程维 | 怎么流转？ |
| 3RP | 权责维 | 谁说了算？ |
| 4RP | 监控维 | 现在什么状态？ |
| 5RP | 调度维 | 怎么纠偏？ |
| 6RP | 孪生维 | 现实在数字空间的投影是什么？ |
| 7RP | 推演维 | 如果 X 变化，会发生什么？ |
| 8RP | 寻优维 | 在所有可能中，哪个最好？ |
| 9RP | 博弈维 | 对手/环境会怎么反应？ |
| 10RP | 迭代维 | 多轮验证后，真正可靠的方案是哪个？ |
| 11RP | 时空维 | 未来趋势如何约束今天的决策？ |
| 12RP | 虚实维 | 数字世界的信号如何影响物理世界？ |
| 13RP | 愿景维 | CEO 的战略意图怎么变成执行参数？ |

### 1.2 三个核心原则

| 原则 | 技术含义 |
|------|---------|
| **虚实闭环** | 所有现实决策必须先经虚拟验证。技术上意味着每次 5RP 执行前，6-10 层必须完成至少一轮推演 |
| **降维输出** | 13 层复杂度压缩为一条可执行指令。10RP 输出的 TOP3 方案必须翻译为 5RP 可识别的结构化指令 |
| **可证伪性** | 每个方案附带失效条件。技术上要求每个输出包含置信区间和敏感度分析 |

## 二、架构边界

### 2.1 13RP 做什么

```
✓ 在虚拟空间中预演多种决策路径
✓ 对多目标（成本/碳排/交期/质量）进行帕累托寻优
✓ 模拟对手/政策/环境变化对方案的影响
✓ 将高层战略意图解析为底层执行参数
✓ 输出可执行的、带置信度的行动指令
```

### 2.2 13RP 不做什么

```
✗ 不替代 ERP/MES/WMS（1-5RP 集成而非替代）
✗ 不做实时工业控制（毫秒级控制属于 PLC/SCADA 范畴）
✗ 不自己训练基础大模型（11-13RP 调用而非训练）
✗ 不替代人工做最终决策（系统输出方案+理由，人做最终审批）
```

### 2.3 与外部系统的关系

```
ERP/MES/WMS ──数据源──▶ 1-5RP（物理现实层）
                        ↓
                    6-10RP（平行模拟层）← 核心自研
                        ↓
GPT/Claude/国产大模型 ←── 11-13RP（愿景驱动层）
```

## 三、核心技术概念

### 3.1 数字孪生（6RP）— 不是可视化，是仿真基座

**常见误解**：数字孪生 = 3D 模型 + 实时数据大屏

**13RP 的定义**：数字孪生是高保真仿真模型，必须满足三个条件：
1. 能独立运行（不依赖实时数据也能推演）
2. 能接受扰动（输入参数可变化）
3. 能输出状态（推演结果可被 7RP 消费）

**技术选型**：Unity 工业版（渲染）+ AnyLogic（离散事件仿真引擎）

### 3.2 方案推演（7RP）— 从"拍脑袋"到"算因果"

**输入**：一个或多个变量变化（如"墨西哥工厂停电 5 天""原材料涨价 30%"）

**处理**：基于 6RP 的孪生模型，用蒙特卡洛方法生成 1000 次随机扰动的因果链

**输出**：三维预测曲面（成本轴 × 碳排轴 × 交期轴）

**关键技术**：离散事件仿真 + 蒙特卡洛采样

### 3.3 多目标寻优（8RP）— 帕累托前沿

**问题**：成本最低的方案可能碳排最高，交期最短的方案可能成本爆炸。不存在"万能最优解"。

**方法**：NSGA-III 进化算法，在多维目标空间中寻找帕累托前沿——所有"不被任何其他方案完全碾压"的解的集合。

**输出**：至少 5 个非劣解，每个附带完整的资源需求清单。

**为什么 NSGA-III**：相比 NSGA-II，III 代在处理 3 个以上目标时表现更好，适合 13RP 的成本-碳排-交期-质量四维场景。

### 3.4 博弈对抗（9RP）— 把对手放进来一起算

**问题**：你的最优方案在竞争对手的反应下可能不再最优。

**方法**：RLlib 强化学习框架，为每个预设对手策略训练一个对抗智能体。

**P0 阶段简化版**：用预设脚本替代 RL 训练，先跑通流程。

### 3.5 实验迭代（10RP）— 平行宇宙

**问题**：一次推演可能有偶然性。

**方法**：K8s 并行编排 100 个独立沙盒，每个沙盒是一套完整的 6→7→8→9 流程，参数略有不同。从 100 个结果中筛选胜率 TOP3。

**漏斗**：1000 条初始方案 → 8RP 筛选 50 个帕累托解 → 9RP 对抗后剩 10 个 → 10RP 输出 TOP3

## 四、数据架构概念

```
ODS 层（操作数据存储）→ 原始数据，不做清洗
         ↓
CDM 层（公共数据模型）→ 统一"时间/空间/实体"三维度
         ↓
ADS 层（应用数据服务）→ 为每个 RP 层提供定制视图
```

每层之间用 Protobuf 传递结构化数据，确保跨层通信的类型安全。

## 五、P0 阶段技术聚焦

P0 只做四件事：

| 编号 | 功能 | 为什么是 P0 |
|:----:|------|------------|
| F-4.1 | 实时监控看板 | 证明"1-5 层能打通"，是全部上层建筑的数据入口 |
| F-6.1 | 孪生场景构建 | 证明"能把现实搬进电脑"，是 7-10 层的前置依赖 |
| F-6.2 | 孪生状态同步 | 证明"数据管道是通的"，是实时性的技术验证 |
| — | 15 分钟闭环 Demo | 证明"13 个维度能串起来跑"，是整个 P0 的存在意义 |

P0 不追求算法精度（那是 P1 的事），只追求**管道跑通**和**核心概念的可演示性**。
