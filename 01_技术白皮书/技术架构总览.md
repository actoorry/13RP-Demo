## 各层投入策略

| 层级 | 策略 | 原因 |
|------|------|------|
| 1-5RP | 采购集成 | 成熟市场，不重复造轮子 |
| 6-8RP | **核心自研** | 算法壁垒，差异化核心 |
| 9-10RP | 自研+开源 | 前沿技术，灵活迭代 |
| 11-13RP | 合作调用 | 依赖大模型生态，可插拔 |

## 研发团队规模

| 组别 | 人数 | 职责 |
|------|:---:|------|
| 核心算法组 | 8-10 人 | 6-10 层算法研发 |
| 集成组 | 5 人 | 1-5 层系统打通与数据接入 |
| 前端/运维 | 4 人 | 看板与孪生界面 + DevOps |

> **注**：以上为 P1-P3 全周期编制（约 17-19 人）。P0 阶段精简为 6 人（前端 ×2、后端、算法/数据、DevOps、PM/演示者），分工详见 `03_P0阶段_MVP/Demo实施计划书.md` 第五章。

## 技术选型（P0 阶段）

> P0 Demo 采用简化技术栈快速验证核心概念，P1 起升级为完整生产级方案。详见 `03_P0阶段_MVP/Demo实施计划书.md` 第二章。

| 用途 | P0 Demo 选型 | P1+ 目标选型 | 说明 |
|------|-------------|-------------|------|
| 数字孪生渲染 | **Three.js**（开源 WebGL） | Unity 工业版 | P0 用简化立方体模型即可，P1 升级高保真渲染 |
| 仿真引擎 | **预计算 JSON + 动画** | AnyLogic 专业版 | P0 不跑真实仿真，P1 替换为 AnyLogic 离散事件引擎 |
| 多目标寻优 | **预编排方案** | 自研 NSGA-III | P0 手工编排 3 个帕累托方案，P1 接入真实算法 |
| 实时看板 | **Vue3 + ECharts 5** | Flink + BI | P0 用 Java MockDataService 模拟推送，P1 接入真实流计算 |
| 后端中台 | **Java 21 + Spring Boot 3.x** | 同左 + K8s 弹性伸缩 | — |
| 云基础设施 | 阿里云 ECS（4C/16G） | 4×16C/32G + GPU/A10 | P0 不需要 GPU（Three.js 客户端渲染） |
| 容器编排 | Docker Compose | Kubernetes | P0 单机部署，P2 起弹性编排 |
