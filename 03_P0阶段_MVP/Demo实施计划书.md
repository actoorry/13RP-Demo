## 一、Demo 定位与核心策略

### 1.1 Demo 是什么

**"13RP一号"** 是一场 15 分钟的**闭门脚本化演示**，面向管理层、种子客户和投资人，目标是让观众在 15 分钟内直观感受到 13RP 区别于所有传统 ERP 的代际差异。

**一句话总结**：一个墨西哥工厂停电 → 系统 5 分钟推演出最优方案 → 输出"今天下午 3 点的 5 条可执行指令"。

### 1.2 核心策略：真 + 假 = "真"

P0 实际只交付 4RP + 6RP，但 Demo 需要展示全部 13 层的效果。策略如下：

| 层级 | Demo 中表现 | 实际实现方式 | 观众感知 |
|:----:|-----------|------------|---------|
| **4RP** 监控看板 | ✅ **真**：实时数据看板 | Java 模拟数据源 + WebSocket 推送 + Vue3/ECharts 渲染 | "真正的实时监控" |
| **6RP** 数字孪生 | ✅ **真**：3D 孪生场景 | Three.js WebGL 渲染，三工厂简化模型（立方体+标签） | "真正的数字孪生" |
| **7RP** 方案推演 | ⚠️ **预计算**：后台跑动画 | 预制的 3 条路径 + 进度条动画 → 观众看到的是回放 | "5 分钟跑了 342 条路径" |
| **8RP** 多目标寻优 | ⚠️ **预计算**：预制方案集 | 预制的 5 个帕累托方案 + 雷达图 | "系统自动找到最优解" |
| **9RP** 博弈对抗 | ⚠️ **脚本化**：预设结果 | 预设的"竞争对手涨价"→胜率变化动画 | "博弈对抗推演完成" |
| **5RP** 指令生成 | ⚠️ **模板化**：预制模板 | 预制的指令模板 + 时间戳自动填充 | "5 条可执行指令" |
| **11-13RP** 愿景层 | ❌ **不展示** | P3 才做，Demo 中不出现 | — |

> **关键原则**：观众看到的界面必须是**真实渲染**的（不是 PPT/视频），后台逻辑可以是预计算的，但**交互必须是真实的**（点击、拖拽、勾选都有响应）。这是 o9 和 Palantir Demo 的共同经验：一个能点的 Demo 胜过一百页 PPT 喵。

|------|----------|-----------|
| **Cosmo Tech** | 网页端交互 Demo（cosmotech.com/demos），含 GenAI Copilot 对话 | 网页端交付，低门槛体验 |

### 2.2 Demo 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| **4RP 监控看板** | Vue 3 + ECharts 5 + TailwindCSS 4 + Element Plus | Composition API 灵活，ECharts 国产开源深色主题效果好，Element Plus 组件丰富 |
| **6RP 数字孪生** | Three.js（WebGL 原生渲染） | 开源免费，与 Vue3 生态无缝集成，简化立方体模型即可满足 Demo 需求 |
| **Demo 中台** | Java 21 + Spring Boot 3.x + WebSocket | 虚拟线程支持 WebSocket 长连接，生态成熟；统一 Java 技术栈 |
| **模拟数据源** | Java MockDataService（@Scheduled 定时任务） | 统一技术栈，无需额外 Python 环境；带高斯噪声的时序数据模拟 |
| **预计算结果** | 手工编排 JSON 方案文件 | 7RP/8RP/9RP 的输出均为预计算的 JSON，包含路径、指标、胜率等字段 |
| **部署** | Docker Compose 一键启动 | 保证演示环境可复现，不受本地环境差异影响 |
| **云环境** | 阿里云 ECS（4C/16G） + 本地 MacBook Pro 备份 | 阿里云做主力演示环境，本地做断网备用 |

### 2.3 为什么 Demo 用 Three.js 而不是 Unity

| 方案 | 优点 | 缺点 |
|------|------|------|
| **方案A**：Unity 工业版 → WebGL 导出 | 3D 渲染效果顶级，可复用 P1 资产 | 年费 6 万，WebGL 包体积大（>50MB），加载慢，与 Vue3 通信需额外桥接层 |
| **方案B（采用）**：Three.js 原生 WebGL | 开源免费，包体小（<2MB），与 Vue3 无缝集成，加载快 | 复杂场景渲染不如 Unity，P1 正式版可能需要升级到 Unity |

**决策**：P0 Demo 采用方案 B。Three.js 渲染简化场景（立方体工厂 + 粒子物流路线 + 标签），满足 Demo 的"看得见"目标。P1 可根据需要评估是否升级到 Unity 工业版喵。

**技术实现**：
- 推演进度条是**预编排动画**（不是真实计算），时长约 120 秒

- 路径文本在 6 个预制路径池中随机轮换显示（模拟真实计算感）
- Three.js 物流路线闪烁：`LineBasicMaterial` opacity 动画 + 颜色过渡（绿→黄→红）
- 预制 JSON 结构：
```json
{
  "total_paths": 342,
  "simulated": 342,
  "perturbations": 1000,
  "top_paths": [
    {"id": "P1", "name": "越南增产+海运补货", "cost": 120, "carbon": 45, "delivery": 28, "risk_score": 0.22},
    {"id": "P2", "name": "中国空运关键部件", "cost": 340, "carbon": 210, "delivery": 3, "risk_score": 0.15},
    {"id": "P3", "name": "墨西哥减产+延长交期", "cost": 80, "carbon": 12, "delivery": 35, "risk_score": 0.38}
  ]
}
```

数据生成核心逻辑（`backend/src/main/java/com/rd13/demo/service/MockDataService.java`）：

```java
@Service
public class MockDataService {
    private final Map<String, FactoryParams> factories = new ConcurrentHashMap<>();

    public MockDataService() {
        factories.put("CN", new FactoryParams(87, 3, 1250, 340, 94, 82, PowerStatus.NORMAL));
        factories.put("VN", new FactoryParams(78, 2, 890, 210, 91, 76, PowerStatus.NORMAL));
        factories.put("MX", new FactoryParams(92, 1, 1420, 180, 96, 88, PowerStatus.NORMAL));
    }

    @Scheduled(fixedRateString = "${demo.data-push-interval-ms:1000}")
    public void generateAndPush() {
        Map<String, FactoryData> tick = new HashMap<>();
        factories.forEach((code, params) -> {
            tick.put(code, FactoryData.builder()
                .capacityUtilization(addGaussianNoise(params.capacity, params.noise))
                .wipInventory((int) addGaussianNoise(params.wip, params.wip * 0.02))
                .finishedInventory((int) addGaussianNoise(params.finished, params.finished * 0.02))
                .deliveryRate(addGaussianNoise(params.delivery, 1.0))
                .oee(addGaussianNoise(params.oee, 2.0))
                .powerStatus(params.powerStatus)
                .build());
        });
        webSocketHandler.broadcastDashboard(tick);
    }

    public void injectPowerOutage(String factoryCode) {
        FactoryParams params = factories.get(factoryCode);
        params.setCapacity(0);
        params.setOee(0);
        params.setPowerStatus(PowerStatus.OUTAGE);
    }

    private double addGaussianNoise(double mean, double stdDev) {
        return Math.max(0, mean + ThreadLocalRandom.current().nextGaussian() * stdDev);
    }
}
```

> **对比旧方案**：原 Unity 方案预算约 2.4 万（Unity 1.5 万 + GPU 0.3 万 + 云 0.5 万 + 设计 0.1 万）。Three.js 方案省去了 Unity 授权费和 GPU 租用费，总节省约 1.75 万喵。

> **口径说明**：本章预算为 P0 软件/云**增量成本**（约 0.65 万），不含人力。与总纲 P0 预算 46 万（人力 30 万 + 硬件/云/外包 16 万）口径不同——16 万中还包含硬件采购（演示机/备份设备）与人力外协（UI/三维素材外包）等科目，本章不展开；执行时以实际采购为准，软件/云部分控制在 1 万以内。
