## 一、三角色工作流

```
┌────────────────────────────────────────────────────────────┐
│ 组长（Hermes 主会话）—— 统筹规划                          │
│  · 任务拆解：产出任务包（目标 + 范围 + 验收标准）          │
│  · 委派：Claude Code 实现 → OpenCode 审查 → 修复循环       │
│  · 端到端验收：浏览器/API 实测，对照 Demo验收场景.md        │
└──────────────────────────┬─────────────────────────────────┘
                           │ 任务包（含文档引用 + 已知坑清单）
                           ▼
┌────────────────────────────────────────────────────────────┐
│ Claude Code（claude -p 打印模式）—— 代码实现               │
│  · 按任务包实现，遵守技术栈锁定与文档契约                   │
│  · 构建/测试必须真实执行（docker compose build 等）         │
└──────────────────────────┬─────────────────────────────────┘
                           │ 代码产出
                           ▼
┌────────────────────────────────────────────────────────────┐
│ OpenCode（opencode run）—— 代码审查                        │
│  · 对照任务包验收标准 + 功能清单逐项核对                    │
│  · 输出：问题清单（严重度 + 位置 + 修复建议）               │
└──────────────────────────┬─────────────────────────────────┘
                           │ 问题清单（有则打回）
                           ▼
                     Claude Code 修复 → OpenCode 复审 → 组长验收 → 下一任务包
```

**流转规则**：
1. 每个任务包必须经历：实现 → 审查 → 修复（如有）→ 组长实测验收，才可关闭
2. 组长实测验收未通过的任务包**打回**，不进入下一包
3. OpenCode 审查发现的安全/正确性问题优先级高于新功能开发
4. 代码目录：`E:\13RP\13RP-Demo\`（组长先建骨架，Claude 填肉）

## 四、传给 Claude Code 的全局约束（每个任务包都附带）

### 技术栈锁定
- 后端：Java 21 + Spring Boot 3.3.x + Maven；前端：Vue3 + Vite + Element Plus + Pinia + ECharts；部署：Docker Compose
- 参考实现：`Demo技术方案与开发手册.md`（目录结构/API/数据流必须遵守）

### 业务数据契约（决策演示）
- 事件：台风"海燕"封港 5 天 → 宁波舟山港/上海港 CLOSED
- 推演：342 条路径、1000 次扰动；核心 3 条：P1 改港青岛+铁路转运 / P2 空运关键物料 / P3 启用备选供应商
- 方案指标：cost/carbon/delivery/risk；偏好：delivery_first / balanced / cost_first
- 博弈因素 4 个：港口拥堵加剧 / 竞争对手抢订舱位 / 台风路径延长 / 客户接受延期
- 指令 5 条/方案，合同要素字段：品名/重量/装货地址/卸货地址/装货时间/卸货时间/结算方式/预算价格/供方数量 + 负责人/截止/单据号/失效条件

### 已知坑清单（组长实测经验，避免重蹈）
1. **Controller 重载**：REST 方法收 `@RequestBody Map`，WebSocket 直调需同名便捷重载（String/int 参数），否则编译失败
2. **final 字段注入**：`private final WebSocketSessionManager ws` 必须在构造函数注入，不能靠字段初始化
3. **WebSocket handler 动作分支**：前端所有 send action（trigger-event/start-simulation/start-optimization/start-gaming/confirm-plan/fast-forward/skip-simulation/reset）必须有对应 case，否则走 default 报"未知动作"
4. **el-radio-group 用 `v-model`**，不要用 `:model-value`（单向绑定点击后选中态不更新）
5. **Map.of 混合类型**：`Map.of("k1", strVal, "k2", mapVal)` 类型推断会失败，用显式 `Map.<String,Object>of(...)` 或 HashMap
6. **PowerShell 传 JSON**：curl `-d` 用单引号包 JSON（双引号会转义错误导致 400）
7. **进度动画**：progress 状态存单一处（TimelineController），更新后经 StateMachine 广播，避免双份进度
8. **前端刷新恢复**：onMounted 拉 `/api/demo/state` 后，按 phase 恢复对应数据（solutions/instructions），否则刷新后 OPTIMIZING 面板空白

### 审查要点（传给 OpenCode）
- 状态机迁移合法性（非法迁移抛错）
- WebSocket 并发会话安全（ConcurrentHashMap）
- 预计算 JSON 与文档字段规范一致
- 前端 TS 严格模式无 any 滥用、无未用变量
- Dockerfile 多阶段构建可复现
